# Guía rápida · GitHub

**Piénsalo como:** una caja fuerte con botón de deshacer.
**Dónde:** `github.com`

---

## Para qué te sirve de verdad

Para que nunca vuelvas a tener:

```
propuesta-final-v3-DEFINITIVA-esta-sí.docx
```

Con GitHub hay **un** archivo y un historial completo. Ves qué cambió, cuándo, y vuelves a como
estaba el martes.

---

## Las cuatro palabras raras

| La palabra | Qué es de verdad |
|---|---|
| **Repositorio** (repo) | La carpeta de tu proyecto, guardada en la nube |
| **Commit** | Una foto de cómo estaba todo en este momento, con una nota |
| **Historial** | Todas las fotos, en orden. Vuelves a cualquiera. |
| **Push** | Subir tus cambios a la nube |

Eso es todo lo que necesitas para empezar. El resto se aprende cuando te haga falta.

---

## Los primeros pasos

1. Cuenta en `github.com` (gratis).
2. **New repository** → nómbralo con tu proyecto.
3. Descripción de una línea.
4. **Público** si quieres mostrarlo, **privado** si es tuyo y punto.
5. Subir tu proyecto.

**La vía fácil:** casi todos los editores con agentes se conectan a GitHub con un botón. Si el tuyo
lo tiene, úsalo — te salta todos los pasos manuales.

---

## Practica deshacer (esto es lo importante)

Es el ejercicio que le quita el miedo a todo:

1. Cambia algo en tu proyecto — un texto, un color.
2. Guárdalo con un commit. Nota: *"probando deshacer"*.
3. Mira el historial: están las dos versiones.
4. **Vuelve a la anterior.**

> Cuando sabes que puedes volver atrás, dejas de tener miedo a cambiar cosas. **Eso** es lo que te
> llevas de GitHub.

---

## Recuerda

- **Un commit cada vez que algo te funcione.** No esperes al final del día.
- **La nota del commit importa.** *"Cambié el color del botón a naranja"* te sirve en un mes;
  *"cambios"* no te sirve nunca.
- **Nunca subas contraseñas, claves ni datos de clientes.** Lo que subes queda en el historial
  incluso si después lo borras.
- Si es privado, sigue siendo tu respaldo. No tiene que ser público para servirte.
